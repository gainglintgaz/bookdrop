# V1 Feature Backlog

Status flow: DISCUSSED -> IN PROGRESS -> DONE -> VERIFIED

All AI-touching features must be designed against `.claude/rules/ai-first-principles.md` and `.claude/rules/data-flywheel.md` and reflected in `DATA_FLYWHEEL.md`.

## Features

| Feature | Status | Priority | Notes |
|---|---|---|---|
| **AI-first architectural pivot (engines move from opt-in Analysis tab to default core flow)** | DISCUSSED | **CRITICAL — blocks V1 launch** | Per `DATA_FLYWHEEL.md` §B, BookDrop currently fails the 5-question audit (1/5 PASS, 3/5 FAIL). The 16 intelligence engines are buried in opt-in Analysis tab. Required pivot work in `DATA_FLYWHEEL.md` §D: (1) auto-categorization runs at upload moment, surfaced to client; (2) reconciliation auto-runs on statement arrival, only unmatched items surface to bookkeeper; (3) reminders adapt per-client (LOCKED with honest copy until Loop 2+ data per client per `ai-first-principles.md` §3 Trust Ladder); (4) bookkeeper-ready package auto-generated at month-end; (5) dashboard sorted by AI-derived urgency score. The Workflow Library row below is the concrete UI manifestation of this pivot. ~2-3 weeks restructuring. Without this, V1 cannot honestly market AI/intelligence claims. |
| **Source-traceable everything (provenance UI on every AI claim)** | DISCUSSED | HIGH (V1 — depends on AI-first pivot) | Logic-transferred from Perplexity Computer's "every output traceable" pattern (May 2026). Adapts CPA-grade provenance: every categorization, reconciliation match, AJE candidate, anomaly flag, and aggregate stat exposes its underlying evidence. Click-to-source UX shape: categorization → "matched rule X (you corrected this 4 times in Mar–Apr)" or "matched 12 firms' median classification (n=12, k=10 met)" or "Gemini Flash with confidence 0.87, source: vendor + amount pattern"; reconciliation match → bank txn row + ledger row + source statement page; AJE candidate → template + last N occurrences. Implements `ai-first-principles.md` §5 anti-fabrication rules 1, 6 + `data-flywheel.md` §8.2 substring validator at the UI layer. ~1 week of work after the AI-first pivot wires the engines into the core flow. CPAs care about provenance more than any other audience — this is non-negotiable. |
| **Client Tearsheet page** | DISCUSSED | HIGH (V1.1 — after pivot ships) | Logic-transferred from Perplexity's "company tearsheet" pattern. New route `/clients/:id/tearsheet` becomes the default landing when CPA opens a client (replaces current Documents-tab landing). One-page snapshot: business summary + intake notes; current period status (X of Y docs uploaded, reconciliation %, anomaly count); 12-month activity sparkline (revenue, expenses, on-time rate) — sparkline is LOCKED with honest copy until Loop 12+ per client (Trust Ladder); open items (missing docs, unreviewed anomalies, AJEs awaiting approval); every number is a clickable source link (depends on Source-traceable Everything row). |
| **Workflow Library (12 pre-built CPA workflows)** | DISCUSSED | HIGH (V1.1 — concrete output of AI-first pivot) | Logic-transferred from Perplexity's "35 finance workflows" pattern, retargeted to CPA work. Each workflow = orchestrated multi-step automation that would otherwise take 30-90 min of manual clicking. Starting set of 12: (1) Month-end close — service business, (2) Month-end close — retail/inventory, (3) Month-end close — payroll-heavy, (4) Year-end close (December), (5) 1099 prep (vendor ≥$600 threshold), (6) Quarterly tax estimate prep — DATA ONLY, no advice (LEGAL_GUARDRAILS.md compliance), (7) Audit prep packet, (8) New client onboarding (intake + first reconciliation + baseline categorization rules), (9) Reconciliation troubleshoot (find the off-by-$X delta), (10) AR aging review, (11) Recurring AJE batch generate (`data-flywheel.md` §15 pattern), (12) Client-meeting Q&A pack. Each workflow runs the existing engines in sequence with right inputs. Dashboard panel "Workflows" — one click runs the orchestration, results land in review queue. |
| **Cross-client portfolio screen (book-of-business filter)** | DISCUSSED | MEDIUM (V1.1) | Logic-transferred from Perplexity's "sourcing screen" pattern. Dashboard panel: "Show me clients matching [criteria]" with pre-baked filters: clients with unreconciled items >30 days; clients with vendors approaching 1099 threshold; clients with anomalies flagged this month; clients overdue on uploads; clients on fiscal year ending this quarter; clients in industries with seasonal patterns starting. Each result shows the signal that matched (provenance from Source-traceable Everything row). Replaces the "open every client one-by-one" workflow that consumes ~30 min per CPA per day. Cross-client aggregate stats ("how many of YOUR clients are usually late on uploads") are k=N gated per `data-flywheel.md` §4 — render LOCKED until threshold met. |
| **Native QuickBooks Online + Xero integration** | DISCUSSED | LOW (V1.2+) | Logic-transferred from Perplexity's "licensed data integration" pattern, retargeted to bookkeeping platforms (Morningstar/PitchBook are the wrong corpus for CPAs). Read GL data via OAuth, post AJEs back to client's QBO/Xero, sync chart of accounts. Eliminates manual export/import workflow. Per-platform connector + unified internal schema preserves the architectural-isolation rules in `strategic-roadmap.md` (no hard FKs into external platforms; data shape stays portable for Stage 3 spin-out). Tracking now sets the architectural direction for the AI-first pivot to leave room. |
| **Outcomes + corrections capture in core flow (Phase A of data flywheel)** | DISCUSSED | **CRITICAL — blocks V1 launch** | Per `DATA_FLYWHEEL.md` §C, corrections are Phase A for BookDrop (not Phase E). Schema additions: `document_uploads.auto_categorized_at`, `auto_categorization_confidence`, `client_confirmed_at`. New table `categorization_corrections(user_id, transaction_id, original_category, corrected_category, reason, created_at)` with RLS `auth.uid() = user_id`. Outcomes capture at close-cycle sign-off: per-cycle hours-saved metric, accuracy %, AI-claim-vs-actual delta. Without this Phase A data, the flywheel never starts spinning. |
| **Recurring AJE Templates (Pro tier differentiator)** | DISCUSSED | HIGH (V1.1 candidate) | CPA pain point: same 12 month-end AJEs × N clients = many hours/month of muscle memory. Schema: `recurring_journal_templates(id, client_id, label, frequency, account_debit, account_credit, amount_cents, last_posted_at, next_due_at, is_active)`. CPA enters AJE once → UI offers "recur monthly through year-end" → cron auto-creates AJE *candidates* each month-end → review queue (NEVER auto-posted, judgment must remain CPA's). Banner: "3 recurring AJEs ready for May month-end review". Diff alert if a candidate looks off-pattern. Per the Trust Ladder, AJE template recommendations are LOCKED until Loop 2+ for the relevant client; surface honest "Unlocks after 2 close cycles" copy until then. |
| **R2 backup pipeline live + first restore drill** | DISCUSSED | HIGH (must complete before going live) | `scripts/backup-pg-to-r2.ps1` and `scripts/RESTORE_DRILL.md` exist as of 2026-05-05. Activation requires: Cloudflare R2 bucket created + token, Wrangler installed, Windows Task Scheduler entry for daily 02:00 backup, 90-day retention policy on R2 (CPA standard), first quarterly restore drill within 30 days of going live. Until done, BookDrop has no off-platform redundancy. CPAs cannot afford a database outage = client churn + malpractice exposure. |
| **Pre-launch bug checklist run** | DISCUSSED | HIGH (must complete before going live) | Run all 13 grep patterns from `.claude/rules/bug-checklist.md` against the codebase. Document hits + resolutions in PR description. False positives must be explicitly noted with reason. |
| **k=N aggregate-suppression layer** | DISCUSSED | MEDIUM (V1.1 — required before any "bookkeepers like you" claim) | Per `data-flywheel.md` §4, every aggregate stat must be suppressed if `<k` distinct contributors. Default k=5; for BookDrop, raise to k=10 because CPA accuracy bar is high. Pure SQL via materialized view; refresh nightly. Show LOCKED state with honest "[N] more contributions needed" until threshold met. Without this layer, any "X bookkeepers say…" is fabricated. |
| **Substring validator for LLM-generated explanations** | DISCUSSED | MEDIUM (required wherever LLM output reaches the user) | Per `data-flywheel.md` §8.2 + `ai-first-principles.md` §5 anti-fabrication. Every LLM-generated categorization explanation, reconciliation rationale, or anomaly description must be substring-validated against the input source. Reject + retry if not. Concrete shape: validator function returns `{ valid: bool, hallucinated_spans: string[] }`; if `valid=false`, surface a real placeholder (per anti-fabrication rule 6), never the hallucinated output. |
| **Hosting cost optimization** | DISCUSSED | MEDIUM | BookDrop currently has its own Supabase project (~$2.85/mo extra compute). Two options without violating the Stage 1+2+3 architectural-isolation rules in `strategic-roadmap.md`: (a) keep standalone Supabase project, accept the cost; (b) move BookDrop to a Neon free-tier Postgres project — saves $2.85/mo, sets a precedent for future projects on Neon free tier. Decision: defer until V1 launches; current cost is not blocking. |
| **OG image for social sharing** | DISCUSSED | LOW | Add `og:image` meta tag — needs a designed image (1200×630 PNG). |
| **Analytics integration** | DISCUSSED | LOW | Optional. Pick a privacy-first analytics provider (PostHog Cloud free tier 1M events/mo, or self-hosted). Must comply with `data-flywheel.md` §8 anti-fabrication and §11 contributor pact (no PII in event logs). |
